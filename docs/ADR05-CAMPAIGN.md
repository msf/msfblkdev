## 1. Plan and freeze the contract (historical evaluation baseline)

Test the released format 4 and its existing checkpoint selection, replay and reuse rules. Do not introduce a checksum-chain encoding or remove stale-tail protection. Keep the existing failure latch while evaluating the engine. Classify discrepancies against a *proposed* online continuation policy separately from violations of the released contract. Before changing that policy, specify what the next request can do after a partial record, uncertain flush, timeout or unavailable ring. Require a proof/test for buffer ownership, no double publication, no reuse of uncertain bytes and the effect of a second error. If safe continuation isn't established, keep the volume failed and record the decision needed.

Use two explicit fault contracts: (a) successful syncs hold and only pending bytes vary; (b) later damage or a lying device, where detection, not durable recovery, can be the correct result. A failed sync adds no promise. Distinguish rejected-before-I/O, successful, and uncertain writes. Track the order across LBAs as well as the allowed values of each one. Start with exact traces and a 4 KiB atomic descriptor model; then split writes into declared sectors/byte ranges. Never claim that the model measures hardware atomicity. Use shared operation names, boundaries, hit counts and observation records, with tier-specific mechanisms. Confirm log replay compatibility before relying on `blklogwrites`. Leave unconditional rules out of the acceptance path.

## 2. Build and run the framework (no product fixes)

| Work item | Implementation and exit check |
|---|---|
| E1. Harness and control | Make a fast Linux developer target and a separate opt-in guest target. Establish the control before using a rule. Pin tools, bound child/suite time and backing writes, verify non-root access and scratch identity, retain failed images and traces outside the fixture. Missing prerequisites or a rule that didn't fire are not a pass. Inventory existing tests and repeat those used as evidence. |
| E2. Injectable backing (delivery 1) | Put an exact-I/O seam underneath format/open, not above ublk. Preserve vectored batching, short/extra CQE and flag checks, discard/growth, ring cleanup and accounting. Compare native formatted bytes at fixed volume ID. Keep old SIGKILL gates until a boundary sweep demonstrably subsumes them. Compare dispatch overhead on the same build/workload. |
| E3. Exact medium and reference history (delivery 2) | Separate pending from durable ranges. Enumerate `EIO`, backing `ENOSPC`, short read/write, delay/timeout, device loss, payload/metadata bit flips, tears, stale or misdirected reads/writes, reordered/lost pending writes. Cover submission vs completion and errors before vs after side effects. Test all four metadata/payload survival combinations. Check startup, online read/write, checkpoint body/descriptor/final sync and subsequent requests independently. Assert no bytes changed on refusal when required. |
| E4. Independent oracles and controls | Extend the logical history checker with cross-LBA prefix/order constraints where required. Parse both selectable roots without calling engine open or trusting allocator counts. Follow mapping/index/table pages, both heads and their replay paths. Verify bounds, references vs free/reused segments, selected LSN/cursors and physical budget. Plant lost durable, wrong LBA, resurrected discard, visible rejected write, skipped barrier, premature reuse and corrupt payload vs metadata controls. Require detection at the named phase; verify a deliberately out-of-range trigger has zero hits. |
| E5. Format, recovery and progress matrix | Corrupt valid and arbitrary bytes including recomputed checksums, reserved kind/high address bits, geometry and overflow. Cover alternate root vs no candidate; healthy/damaged/overwritten payload; partial-tail vs recognizable corrupt record; identical tail reuse; interrupted growth and repeated reopen. At A/B barriers cover relocation, metadata-only victim, stale cleaner proposal, delayed discard vs allocation and both roots after later reuse. Bound cleaner handoff schedules under full queues, reserve pressure, idle and shutdown; don't demand progress from an all-live volume. |
| E6. Live error gate (delivery 3) | From a normal-user ublk client through the daemon and real `io_uring`, target one checkpoint-B descriptor write and one final sync on separate fixtures. Arm at the boundary, verify operation identity, hit count, errno/deadline, victim contents and absence of allocation/hole punch after failure. Recover a **copy** against externally recorded flushes. Add read, log-write, recovery, ENOSPC and short completion cases only on mechanisms that implement them. Qualify on native arm64 and amd64 guests and the supported providers separately. |
| E7. Seeded exploration | After the corresponding planted controls pass, generate bounded overwrite/discard/flush/reopen/growth sequences on fresh and pre-reused images. Record exact I/O event and schedule traces as well as seeds. Vary cache size, batch and checkpoint interval; account for changed flush boundaries. Reduce failures by deleting operations and shrinking addresses/fault ranges. Preserve the smallest reproducer found as a fixed test. |
| E8. Operator-only medium and apps (delivery 4) | With separate operator approval, use owned disposable VM loop files and `dm-flakey`/`dm-log-writes`; verify identity before privileged actions. Replay selected captured flush/FUA order and early-reuse controls. Run the accepted ADR-06 filesystem/database gates with an external transaction history, offline checks and safe remount. Do not automate this tier on the host. No physical power-loss or distributed scheduling claim. |

Evaluate E1/E3 fixed cases and E6 on independent fixtures first. E4's controls gate E7. E8 depends on E4/E6 and the operator runbook. Reconcile new gates with ADR-03/06 before replacing any regression. Compare failures only between tiers whose fault contracts overlap.

## 3. Triage and checkpoint before repairs

For each matrix row record tested format/build, phase, logical operation, fault/side effects, expected vs observed caller outcome, backing state, hit count, copy-before-open and checker verdict. Distinguish **confirmed defect** from **policy gap**, **checker/harness defect**, **injected expected damage**, **suspected**, **pass** and **not run**. Rank by impact: lost flushed data or unsafe reuse; fail-open corruption or incorrect publication; hang/crash; availability-only; lab/reporting error. Give each confirmed defect an ID, reproducible command, minimal input or artifact hash and a failing assertion. A proposed behavior missing in production isn't by itself a bug. A green subset doesn't prove a class is absent.

Commit evaluation tooling separately from transcripts, then commit the triage inventory (including uncovered classes) and tag it before editing the engine. Compare each repair with that tag, not a moving working tree. Checkpoint subsequent batches the same way. Don't silently reclassify an old failing run.

## 4. Fix and qualify

Repair one confirmed root cause at a time in descending impact. Run its same reproducer before/after and the matching negative control; record the first good commit and passing trace. Keep product fixes separate from harness changes and intentional policy decisions. Run `make lint test`, full crash acceptance and the affected ublk/filesystem gates before a release candidate. Retain before/after images, kernel/toolchain/ISA identities, exact budgets and all gaps. Close ADR-05 only after the matrix has evidence or an explicitly accepted exclusion, the online policy and ABI decisions are recorded, required operator/native rows ran, and no release-blocking result remains. Multi-node deterministic scheduling remains a separate proposal.
